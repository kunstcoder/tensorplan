## MVP

| ID | 기능 |
|---|---|
| F01 | 모듈 계층 트리 (루트 모델 탐색, 인스턴스 경로, 클래스·주요 인자·정의 위치) |
| F02 | 반복 블록 접기. 클래스와 생성 인자가 **모두** 같은 형제만 `×N` 으로 접고, 다르면 `p s c s c s` 같은 패턴으로 보인다 |
| F03 | 파라미터 수·크기·비중 (모듈별·전체, dtype별 바이트, 공유 가중치 중복 제거) |
| F04 | 모든 수치에 출처 태그(코드 추정 / 설정 / 가중치 / 실행). 모르는 값은 `?` 와 이유, 그런 값이 섞인 합계는 `≥` |
| F05 | 로컬 safetensors 헤더 교차 검증 (✓/✗) |
| F06 | 입력·출력 계약과 기호 차원 사전 (`[B, N, 3]`, `D=192, H=3, d_h=64`) |
| F08 | 모듈 설명·논문 대응·투어 |
| F09 | 모델 Ask 바 (수치는 조회 도구로 계산하고 LLM 암산 금지) |
| F07 | 블록 흐름도(shape 라벨). **MVP 의 마지막 순서**: 시간이 되면 넣고 아니면 빼고 먼저 낸다. LLM 이 forward 를 읽어 그리므로 shape 는 "추정"이다 |

## 단계

- **MVP**: 처음 쓸 수 있는 최소 버전(위 표).
- **v1**: MVP 다음 단계(P1). 옵트인 런타임 추적(실측 shape, 학습/동결), FLOPs, 메모리 정확 산술(가중치·옵티마이저·KV 캐시), 구조 diff·CI 요약, 모델 점검, 어텐션/MoE 카드, 체크포인트만으로 지도, pickle 정적 스캔(opcode 만 읽음), 모델 카드·Mermaid 내보내기, 용어 툴팁.
- **v2**: 수요가 확인된 뒤(P2). 입력 크기 what-if, 활성값 메모리, 두 모델 비교, 논문 PDF 대응, ONNX·JAX 등 다른 형식.
- 기술 검토는 같은 내용을 Phase 1/2/3 으로 나눴다. Phase 1 = MVP, Phase 2·3 = v1 의 일부씩이다. 런타임 추적은 기획 안이 v1 첫 항목, 기술 안이 Phase 3 이라 시점이 다른데, 이 결정은 기획 안(v1 첫 항목)을 따른다.

## 하지 않을 것

프로파일러(지연·처리량), op 수준 대형 그래프 뷰어, 학습 모니터링, 가중치 값 분석, `torch.load` (pickle 은 opcode 정적 스캔만), 사용자 동의 없는 코드 실행·패키지 설치, 코드·가중치의 외부 업로드, MVP·v1 의 TF/Keras/JAX 정식 지원.

## 일정 추정

기술 검토: 새로 쓰거나 고칠 코드 약 4,000~7,000줄, 숙련 개발자 1명 기준 3~5주(Phase 1). 기획의 "1주"는 낙관적이었다. F07 을 뺐을 때 얼마나 줄어드는지는 추정하지 못했다.

## 유실

임시 폴더(scratchpad)에 있던 제품 기획서(539줄)와 기술 검토 보고서(617줄), 실험 스크립트·출력, floorplan 클론이 정리로 사라졌다. 워커 기록에서 복구를 시도했으나 긴 입력이 잘려 있어 원문을 되살리지 못했다. 이 문서와 `UPSTREAM.md` 는 대화에서 읽은 부분과 이후 직접 확인한 사실로 다시 쓴 것이다. 되살리지 못한 것은 페르소나·시나리오, 화면 스케치와 "처음 5분", Ask 대표 질문 20개, 모델 점검 목록, 성공 기준, 신뢰·안전 요구 상세다.
